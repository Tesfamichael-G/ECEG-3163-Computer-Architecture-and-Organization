    ECEG-3163¶

    Chapter 3 — Instruction Sets and CPU Structure¶

    3.1 — Instruction Set Taxonomy¶

    Where do operands come from?
    Class Operands live in... Example
    Stack top of a pushdown stack Java bytecode
    Accumulator one special register early 8-bit CPUs
    General-purpose many named registers x86, ARM, MIPS
    Register-memory one operand in memory x86
    Load-store all operands in registers MIPS, ARM, RISC-V
    !!! tip "Load-store is the RISC foundation" Only `LOAD` and `STORE` touch memory; all ALU operations are register-to-register. Simple to pipeline, simple to optimize.

    3.2 — MIPS Instruction Formats¶

    R-type — register-to-register 
    | opcode 6 | rs 5 | rt 5 | rd 5 | shamt 5 | funct 6 |

    Example: add rd, rs, rt → 000000 rs rt rd 00000 100000.

    ???+ note "I-type — immediate" 
    | opcode 6 | rs 5 | rt 5 | imm16 |
    Example: `addi rt, rs, imm`, `lw rt, offset(rs)`, `beq rs, rt, offset`.
    ???+ note "J-type — jump" 
    | opcode 6 | target 26 |
    Target = `(PC+4)[31:28] || target << 2` — 28 bits of address from 26-bit field.

    Worked example 3.1 — Decode 0x012A4020¶

    Problem:

    Decode the MIPS instruction 0x012A4020.

    ???+ note "**Step 1 — binary.**" $\texttt{0000\,0001\,0010\,1010\,0100\,0000\,0010\,0000}$
    ??? info "**Step 2 — split fields.**" | Field | Bits | Value | |---|---|---| | opcode | `000000` | R-type | | rs | `01001` | 9 | | rt | `01010` | 10 | | rd | `01000` | 8 | | shamt | `00000` | 0 | | funct | `100000` | `add` |
    ??? success "**Step 3 — decode.**" $\texttt{add\ \$8,\ \$9,\ \$10}$ — register 8 = register 9 + register 10.

    3.3 — Addressing Modes¶

    Eight classic modes
    Mode Effective address (EA) Memory accesses
    Immediate operand embedded in instruction 0
    Register operand in register 0
    Direct EA = address field 1
    Indirect EA = M[address field] 2
    Register indirect EA = R[field] 1
    Displacement (base+offset) EA = R[base] + offset 1
    Indexed EA = R[index] + address field 1
    Relative EA = PC + offset 1
    !!! tip "The base+offset workhorse" Base+offset handles **arrays** (base = array start, offset = index×stride), **structs** (base = struct, offset = field), and **stack frames** (base = frame pointer, offset = local) — all with the same encoding.

    Worked example 3.2 — Effective addresses¶

    Problem:

    Suppose R[5] = 0x1000. Compute the effective address for each mode.

    ???+ note "**Immediate `lw $t0, 100`**" The value 100 is an immediate, not an address. There is no memory access for the operand itself.
    ??? info "**Direct (address field 100)**" EA = 100. One memory access.
    ??? info "**Register indirect `lw $t0, 0($5)`**" EA = R[5] + 0 = 0x1000. One memory access.
    ??? info "**Base+offset `lw $t0, 8($5)`**" EA = R[5] + 8 = **0x1008**. One memory access.
    ??? success "**Indirect `lw $t0, @100`**" Read M[100] → gives address A; read M[A] → gives operand. **Two memory accesses.**

    3.4 — CPU Registers¶

    The essential registers
    Register Purpose
    PC Program counter — address of next instruction
    IR Instruction register — current instruction
    MAR Memory address register
    MBR / MDR Memory buffer / data register
    R0..Rn General-purpose registers
    SP Stack pointer
    FLAGS / PSW Condition codes (Z, C, S, V)
    !!! tip "PC + IR = the Von Neumann loop" The **PC** sequences the fetch; the **IR** holds the fetched instruction long enough to be decoded. Without either, there is no instruction cycle.

    3.5 — Register Transfer Notation¶

    RTN describes data movement and operations 
    MAR ← PC
MBR ← M[MAR]
IR  ← MBR
PC  ← PC + 4
    ???+ note "Fetch cycle in RTN" 
    T0: MAR ← PC
T1: MBR ← M[MAR],  PC ← PC + 4
T2: IR  ← MBR
    Three cycles on a **single-bus datapath** — one transfer per cycle.
    !!! tip "RTN is the bridge between ISA and hardware" Each line of RTN corresponds to one or more control signals. The control unit (Chapter 4) translates the RTN into actual microoperations.

    3.6 — Datapath¶

    Three datapath designs
    Design Cycles per instruction Clock period Trade-off
    Single-cycle 1 Longest path Simple, slow
    Multi-cycle 3–5 Short Balanced, more control
    Pipelined ~1 (steady state) Short Fast, complex
    !!! warning "The single-cycle cost" In a single-cycle datapath, every instruction waits for the **slowest** one — usually `LOAD` (memory read). Fast instructions like `ADD` waste most of the cycle.

    3.7 — RISC vs CISC¶

    The two philosophies
    Feature RISC CISC
    Instruction length Fixed Variable
    Instruction count Few, simple Many, complex
    Operand sources Registers only Registers or memory
    Registers Many (32+) Few (8–16)
    Addressing modes Few Many
    Control Hardwired Microprogrammed
    CPI Near 1 2–10
    Code size Larger Smaller
    Pipelining Easy Hard
    Examples MIPS, ARM, RISC-V x86
    ??? info "The RISC argument (1980s)" Most CISC instructions were **rarely used**; compilers could generate efficient code from a small RISC subset; simple instructions pipeline better; register-only operands are faster.
    !!! tip "The modern synthesis" Modern x86 CPUs decode CISC instructions into **RISC-like micro-operations** internally. Today's RISC/CISC distinction is about the **external ISA**, not the microarchitecture.

    Chapter 3 — key takeaways¶

    **1.** **Load-store** ISAs keep ALU operands in registers — only `LOAD`/`STORE` touch memory.
    **2.** **MIPS** has three formats: **R** (register), **I** (immediate), **J** (jump). Decode by splitting the 32-bit word.
    **3.** **Base+offset** addressing is the workhorse — it handles arrays, structs, and stack frames with the same encoding.
    **4.** **RTN** is the bridge between ISA and hardware: each line corresponds to one or more control signals.
    **5.** **RISC** = simple, fixed-length, load-store, easy to pipeline. **CISC** = complex, variable-length, memory operands, microcoded. The boundary is blurred in modern microarchitectures.
